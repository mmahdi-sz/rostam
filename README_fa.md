# rostam — ربات رسانه و ابزار تلگرام

[English](README.md) · **فارسی**

رباتی چندزبانه برای تلگرام (نوشته‌شده با Rust، کریت `ros-telegram-bot`) — رابط
کاربری به فارسی، انگلیسی و ایتالیایی (با دستور `/language` جابه‌جا می‌شود) — که یک
جعبه‌ابزار رسانه‌ای را در دل خود دارد: دانلود یوتیوب، جداسازی صدا (وکال/موسیقی)،
تبدیل گفتار به متن، حذف نویز صدا، بزرگ‌نمایی تصویر، حذف واترمارک، فشرده‌سازی PDF،
جست‌وجوی IP و بسته‌های ایموجی سفارشی — همه پشت یک رابط رتبه‌بندی‌شده/پولی. بیشترِ
مدل‌های هوش مصنوعی **به‌صورت محلی و درون‌فرایندی** اجرا می‌شوند (ONNX، CTranslate2،
Vosk)؛ بقیه‌ی کارهای سنگینِ پردازنده در سرویس‌های جانبی اجرا می‌شوند که با یک
CPU-broker مبتنی بر Redis هماهنگ می‌گردند.

## نصب سریع (روی سرور خام)

روی یک سرور تازه‌ی **Debian/Ubuntu** یا **Arch**، یک دستور همه‌چیز را برپا می‌کند:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mmahdi-sz/rostam/master/install.sh)
```

نصب‌کننده به‌صورت خودکار با `sudo` بالا می‌آید، مخزن را در `/opt/rostam` کلون می‌کند
و کل پشته را برپا می‌سازد. **idempotent** است — اجرای دوباره‌اش امن است. هنگام نصب،
`BOT_TOKEN` (و برای Bot API محلی، `api_id`/`api_hash` تلگرام) را از شما می‌پرسد.

> نصب‌کننده حدود ۴.۲ گیگابایت مدل دانلود
> می‌کند و ربات Rust (و اختیاراً سرور Telegram Bot API) را از سورس می‌سازد — اجرای
> اول کمی طول می‌کشد و به حدود ۱۲ گیگابایت فضای خالی نیاز دارد.

### گزینه‌های نصب‌کننده

```
--dir <path>      محل نصب (پیش‌فرض /opt/rostam)
--branch <name>   شاخه‌ی گیت (پیش‌فرض master)
--skip-bot-api    از ساختن سرور Telegram Bot API محلی صرف‌نظر کن
--skip-firefox    فایرفاکس (رفرش‌کننده‌ی cookie-pool) را نصب نکن
--fresh           از صفر دوباره کلون/بیلد کن
```

## معماری

> نمودار به‌صورت اصلی (انگلیسی/ASCII) نگه داشته شده است.

```
                       ┌──────────────────────────┐
   Telegram  ─────────►│  local Bot API  :8081     │  (2 GB uploads)
                       └────────────┬─────────────┘
                                    │
                          ┌─────────▼─────────┐        ┌───────────────────┐
                          │  rostam (Rust)    │───────►│  in-process ML     │
                          │  target/release/  │        │  ort  (Moebius)    │
                          └───┬───────┬───┬───┘        │  ct2rs (NLLB)      │
             ┌────────────────┘       │   └───────┐    │  vosk (STT)        │
             │                        │           │    └───────────────────┘
      ┌──────▼──────┐          ┌──────▼──────┐  ┌─▼────────────┐
      │ PostgreSQL  │          │   Redis     │  │  Firefox     │
      │  :5432      │          │   :6379     │  │  cookie pool │
      └─────────────┘          └──────┬──────┘  └──────────────┘
                                      │
                          ┌───────────┴───────────┐
                          │      CPU broker        │  (queue + core reservation,
                          │   hosted on :6589      │   Redis-backed)
                          └───────────┬───────────┘
                            ┌─────────┴─────────┐
                    ┌───────▼────┐      ┌───────▼────┐
                    │ separation │      │  surge dl  │
                    │   :6589    │      │   :1700    │
                    └────────────┘      └────────────┘
```

ربات به Postgres، Redis و سرویس‌های جانبی **با تنبلی (lazy)** وصل می‌شود — هیچ‌کدام
هنگام راه‌اندازی الزامی نیستند. اگر Postgres پایین باشد، ربات با پایداری غیرفعال کار
می‌کند؛ اگر یک سرویس جانبی پایین باشد، فقط همان قابلیت پیام «سرویس در دسترس نیست»
می‌دهد. تنها الزامِ سختِ راه‌اندازی، `BOT_TOKEN` است.

سنگین‌ترین مدل‌های هوش مصنوعی **درون‌فرایندی** و داخل خودِ باینری Rust اجرا می‌شوند
(بدون رفت‌وبرگشت به پایتون): اینپینتینگ واترمارک با رانتایم ONNX یعنی `ort`، ترجمه‌ی
زیرنویس با `ct2rs` (CTranslate2)، و تبدیل گفتار به متن با `vosk`. فقط جداسازی صدا و
دانلودهای مستقیمِ موازی در سرویس‌های جانبی هستند. هر کار سنگینِ چندثانیه‌ای — چه
درون‌فرایندی چه جانبی — از طریق **CPU broker** (پورت ۶۵۸۹) زمان‌بندی می‌شود که کار را
صف می‌کند و هسته‌های فیزیکی را از طریق Redis رزرو می‌کند تا کارهای هم‌زمان سرور را
از پا درنیاورند.

## خط‌لوله‌ی هوش مصنوعی و یادگیری ماشین

هر مدلی **به‌صورت محلی** اجرا می‌شود — بدون API خارجیِ هوش مصنوعی، بدون هزینه‌ی
هر-فراخوانی، و بدون خروجِ داده از سرور.

| قابلیت | مدل / موتور | محل اجرا |
|---|---|---|
| **ترجمه‌ی زیرنویس** | **NLLB** متا از طریق `ct2rs` (بایندینگ نیتیو CTranslate2) | درون‌فرایندی |
| **تبدیل گفتار به متن** | **Vosk** (فارسی + انگلیسی، مدل کوچک و بزرگ) | درون‌فرایندی (`libvosk.so`) |
| **حذف نویز صدا** | **DeepFilterNet 3** (باینری `deep-filter`، ONNX) | زیرفرایند |
| **بزرگ‌نمایی تصویر** | **Real-ESRGAN** (ncnn-vulkan): مدل عکس + انیمه (x2/x3/x4) | زیرفرایند |
| **حذف واترمارک** | اینپینتینگ ONNX **Moebius** (کریت `ort`) | درون‌فرایندی |

- **ترجمه‌ی زیرنویس** — وقتی ویدیویی زیرنویس فارسی ندارد، ربات زیرنویس انگلیسی (SRT)
  را می‌گیرد، از مترجم محلی NLLB (`src/youtube/translator/`) عبورش می‌دهد و
  `translated_fa.srt` را با حفظ کاملِ تایمینگ اصلی تولید می‌کند.
- **STT** — زبان و اندازه‌ی مدل را از یک کیبورد این‌لاین انتخاب کنید. مدل‌های بزرگ
  («دقیق») پی‌وال دارند؛ مدل‌های کوچک رایگان‌اند. پیش از تبدیل، می‌توان یک مرحله‌ی
  حذف نویز DeepFilterNet را روشن/خاموش کرد.
- **بزرگ‌نمایی** — یک مد عکس، به‌علاوه‌ی یک کلید اختصاصی **انیمه** که مدل‌های
  `realesrgan-x4plus-anime` و `realesr-animevideov3` را در x2/x3/x4 در دسترس
  می‌گذارد.

## یوتیوب — قابلیت‌های پیشرفته

- **تشخیص خودکار پلی‌لیست** — لینک پلی‌لیست باز می‌شود (`--flat-playlist`)، کاربر
  کیفیت را **یک‌بار** انتخاب می‌کند، سپس هر آیتم در یک حلقه دانلود می‌شود با یک پیام
  وضعیتِ زنده‌ی سنجاق‌شده؛ خطای هر آیتم گزارش می‌شود بدون آنکه کل دسته لغو شود.
- **انتخاب کیفیت و کدک** — رزولوشن، کدک ویدیو، زبان صدا و کیفیت فقط-صدا
  (بهترین / 128k / 64k) همه از یک پنل این‌لاین انتخاب می‌شوند.
- **زیرنویس نرم (soft-sub)** — زیرنویس embed شده به‌صورت `mov_text` با
  `displayFlags=0` نوشته می‌شود تا پخش‌کننده‌ها تراک را *فهرست* کنند ولی به‌زور نشان
  ندهند. بعد از دانلود embedded، ربات ۴ بایت را درجا وصله می‌کند (اولین tx3g فعال →
  `0xC0000000`) تا VLC و امثالش درست رفتار کنند، بدون remux — و از `-c copy` جان
  سالم به‌در می‌برد.
- **دو حالت زیرنویس** — دانلود به‌صورت فایل جدای `.srt`، یا **embed** داخل کانتینر.
- **حل چالش جاوااسکریپت** — به yt-dlp یک رانتایم `deno` داده می‌شود
  (`--js-runtimes`) تا چالش‌های پلیر جاوااسکریپتِ یوتیوب حل شوند (بدون آن فقط
  storyboard می‌گیرید).

## کوکی‌پول و سیستم ضد بن

یوتیوب به‌شدت محدودیت‌سرعت و بنِ IP می‌زند؛ کوکی‌پول بار را روی چندین لاگینِ گوگل
پخش می‌کند تا هیچ حسابی به‌تنهایی نسوزد.

- **چرخش (Rotation)** — هر درخواست کوکیِ در دسترسِ بعدی را از میان یک استخر از
  پروفایل‌های Firefox (`cookies.sqlite`) به‌صورت نوبتی برمی‌دارد، و آخرین کوکیِ
  استفاده‌شده در Postgres ذخیره می‌شود.
- **Cooldown** — کوکی‌ای که `429` می‌خورد در یک جدول cooldown پارک می‌شود
  (`cookie_pool_cooldowns`، Postgres + حافظه) و تا پایان پنجره‌اش نادیده گرفته
  می‌شود؛ حلقه‌ی اصلی خودکار بازش می‌گرداند.
- **رفرش خودکار** — یک تسک پس‌زمینه (`spawn_cookie_refresher`، پیش‌فرض هر ۶۰۰
  ثانیه) یک پروفایل واقعی Firefox را می‌راند تا نشستِ گوگل — و در نتیجه کوکی‌ها —
  تازه بماند.
- **عملیات دستی** — `/cookie_status`، `/cookie_next`، `/cookie_429` استخر را بازبینی
  و دستی هدایت می‌کنند.

وضعیت با سه جدول از ری‌استارت جان سالم به‌در می‌برد: `cookie_pool_cookies`،
`cookie_pool_state`، `cookie_pool_cooldowns`.

## CPU broker و صف کار

هر کار سنگینِ چندثانیه‌ای (جداسازی، بزرگ‌نمایی، واترمارک، ترجمه، حذف نویز) از یک
**بروکر مبتنی بر Redis** عبور می‌کند که سرویس separation روی پورت `6589` میزبانی‌اش
می‌کند:

- `POST /cpu/acquire` مجموعه‌ای از هسته‌های فیزیکی را برای فراخوان رزرو می‌کند؛ کار
  پین‌شده روی آن‌ها اجرا می‌شود و در پایان آزاد می‌کند.
- `GET /cpu/status` هسته‌های در دسترس، طول صف و یک فلگ `overloaded` را گزارش می‌دهد،
  تا ربات به‌جای از پا درآوردن سرور به کاربر بگوید «سیستم مشغول است، در صف».
- کار **صف** می‌شود، نه اینکه دور ریخته شود — فراخوان‌ها نوبتشان را صبر می‌کنند
  (تایم‌اوتِ جداسازی ۴۰ دقیقه است تا صف + پردازش را پوشش دهد).

این جلوی آن را می‌گیرد که چند کار سنگینِ هم‌زمان CPU را بیش‌ازحد اشغال کنند و حلقه‌ی
رویدادِ تلگرام را گرسنه بگذارند.

## رتبه‌ها، پی‌وال و کوتاها

پنج رتبه، به‌ترتیب صعودی: **دلاور** (رایگان) → **سپهبد** → **اسفندیار** →
**سهراب** → **رستم**.

- رتبه‌ی مؤثر روی هر کلیکِ پی‌وال‌دار **زنده** خوانده می‌شود
  (`rank::effective_rank`) — هرگز کش نمی‌شود — و از طریق `user_ranks.expires_at`
  منقضی می‌شود.
- **دکمه‌ها همیشه دیده می‌شوند**؛ پی‌وال روی کلیک شلیک می‌شود، تا رتبه‌های پایین‌تر
  ببینند چه چیزی را از دست می‌دهند.
- پی‌وال‌دار: کیفیت یوتیوب، زیرنویس یوتیوب، ترافیک یوتیوب (روزانه + ماهانه، تخمین از
  بیت‌ریت × مدت)، حذف نویز، مدل‌های دقیق STT، کوتای STT، کوتای جداسازی، کوتای
  بزرگ‌نمایی تصویر.
- کوتاها در `user_quotas` هستند (به‌ازای هر کاربر، هر نوع، پنجره‌ای).

## سیستم دعوت (ضد تقلب)

لینک دعوت: `https://t.me/{bot}?start={referrer_id}`.

- یک `/start` با payload عددی یک دعوتِ **در انتظار** ثبت می‌کند
  (`referral_pending`) — بلافاصله امتیاز **نمی‌دهد**.
- یک sweeper ساعتی (`sweep_confirm`) ردیف‌های در انتظارِ قدیمی‌تر از
  **`PENDING_DAYS` = ۲** را دوباره چک می‌کند: اگر دعوت‌شده هنوز عضو قفل اجباری باشد
  به `referrals` ارتقا می‌یابد (۱ امتیاز)؛ اگر ترک کرده باشد، ردیف دور ریخته می‌شود.
  این حلقه‌ی تقلبِ «جوین → شمرده‌شدن → لفت» را از بین می‌برد.
- امتیازها **خرج** می‌شوند تا یک رتبه را برای **۳۱ روز** فعال کنند، از طریق یک
  پلکانِ مخصوصِ رفرال (`TIERS`): سهراب = ۱۰، اسفندیار = ۲۰، رستم = ۵۰. موجودی =
  `COUNT(referrals) − SUM(points_spent)`. تنزل رتبه رد می‌شود.
- **نکته‌ی مهم**: رفرال به یک قفل اجباریِ الزامی نیاز دارد — بدون آن `is_joined()`
  همیشه true است و هر دعوتِ در انتظار خودکار تأیید می‌شود.

## کدهای هدیه (Redeem)

- ادمین‌ها کدها را از پنل می‌سازند، با فلگ‌هایی به هر ترتیب: `30d es 1u` → ۳۰ روز،
  رتبه‌ی اسفندیار، ۱ مصرف (`<n>d` = روز، `<n>u` = تعداد مصرف، مخفف رتبه
  `da/se/es/so/ro`).
- کدها ۸ کاراکترند از یک الفبای بدون ابهام (بدون `0/O/1/I`) تا روی deep-linkِ
  `?start=` تلگرام تمیز سوار شوند.
- **انقضای کشویی ۷ روزه**: کد با `now + 7d` متولد می‌شود؛ هر مصرف پنجره را ریست
  می‌کند؛ بعد از انقضا جارو می‌شود (`spawn_redeem_sweeper`).
- `max_uses` سقف مصرف را می‌گذارد؛ `redeem_redemptions` (کلید اصلی `code,user_id`)
  یک‌بار-مصرف-به‌ازای-هر-کاربر را اجبار می‌کند.

## سیستم قفل اجباری (Force-join)

یک قفلِ عضویتِ اجباریِ کانال که بعد از انتخاب زبان و پیش از هر قابلیت اجرا می‌شود:

- عضویت **در Redis کش می‌شود** تا قفل روی هر عمل به API تلگرام فشار نیاورد.
- کش با **شنودِ آپدیت‌های `chat_member`** گرم نگه داشته می‌شود
  (`on_chat_member_update`) — لحظه‌ای که کاربر جوین یا لفت می‌دهد، Redis با صفر
  فراخوانیِ اضافیِ API آپدیت می‌شود.
- دکمه‌ی سبزِ «عضو شدم» یک بازبینیِ **زنده** را اجبار می‌کند و کش را دور می‌زند.

قفل اجباری همچنین لنگرِ اعتمادِ تأییدِ رفرال است (بالا را ببینید).

## پنل ادمین و پایش

کال‌بک‌های فقط-ادمین (`admin:panel`)، محدودشده با `ADMIN_USER_ID`:

- **آمار** — شمارشِ رویدادِ هر فیچر (`stats_events`) و شمارشِ کاربران
  (`stats_users`).
- **ترافیک** — بایت‌های دانلود/آپلودِ هر کاربر و موفقیتِ آپلود
  (`stats_downloads`)؛ زمان اولین آپلود روی `stats_users` مهر می‌خورد.
- **خطاها (۲۴ ساعت گذشته)** — هر خطای فیچر ثبت می‌شود (`stats_errors`، سقف ۵۰۰
  کاراکتر) و روی درخواست رندر می‌شود، تا بتوانید خطاها را از داخل تلگرام تریاژ کنید.
- **عملیات** — قفل اجباری را مدیریت کنید و کدهای هدیه بسازید بدون ترک چت.

## Trace logging (لاگ‌گیری ردیابی)

هر عمل کاربر یک **trace id** یکتا حمل می‌کند که در هر هِلپر رشته می‌شود، تا
`rg trace=N` کلِ عمل را به‌ترتیب بازپخش کند. دو نوع خط:

```
[<domain> trace=N actor] user=@<u> id=<id> rank=<R> clicked=<cb>    # یک‌بار، در ورود
[<domain> trace=N event=<step>] k=v => ok|fail err=..|pass|blocked  # هر مرحله، قبل از اجرا
```

نبودِ یک خطِ event یعنی آن مرحله هرگز اجرا نشده — خودِ *نبودن* سیگنال است. مثال
(در acquire کردنِ CPU شکست می‌خورد — `cores=[]` نشانه‌ی جرم است):

```
[upscale trace=43 actor] user=@parsa id=671234… rank=Dalavar clicked=upscale:model:realesrgan-x4plus
[upscale trace=43 event=quota_check] used=2 limit=3 => pass
[upscale trace=43 event=cpu_acquire] => cores=[]
```

با `journalctl -u rostam -n 300 | rg trace=` دنبال کنید.

## تاریخ‌های جلالی (شمسی)

همه‌ی تاریخ‌های روبه‌کاربر جلالی‌اند. تبدیل از نظر منطقه‌ی زمانی درست است — هرگز
دستی نوشته نشده: `DateTime::from_timestamp` → `.with_timezone(Asia::Tehran)` →
`youtube::jalali::gregorian_to_jalali` (به `rank/panel.rs::fmt_jalali` نگاه کنید).

## پیکربندی (`.env`)

نصب‌کننده فایل `.env` را از روی `.env.example` می‌سازد. مقادیر کلیدی:

| متغیر | کاربرد |
|---|---|
| `BOT_TOKEN` | **الزامی** — از @BotFather |
| `ADMIN_USER_ID` | آیدی تلگرامِ دارای دسترسی پنل ادمین + مدیریت کش ایموجی |
| `DATABASE_URL` | `postgres://postgres:postgres@localhost:5432/ros_telegram_bot` |
| `REDIS_URL` | پیش‌فرض `redis://127.0.0.1:6379` |
| `BOT_API_BASE_URL` | `http://127.0.0.1:8081` (Bot API محلی؛ خالی → API رسمی، سقف ۲۰ مگابایت) |
| `DENO_PATH` | مسیر باینری deno (پیش‌فرض `/opt/deno/bin/deno`) |
| `IPINFO_TOKEN`، `ABUSEIPDB_KEY` | غنی‌سازی اختیاریِ جست‌وجوی IP |

همه‌ی مسیرهای قابلیت‌ها (`files/models/*`، `config/i18n.json`) **نسبت به دایرکتوری
کاریِ ربات** (`/opt/rostam`) حل می‌شوند، پس یونیت systemd مقدار `WorkingDirectory`
را متناسب با آن تنظیم می‌کند.

## به‌روزرسانی

```bash
cd /opt/rostam
git pull
cargo build --release
sudo systemctl restart rostam
```

یا نصب‌کننده را دوباره اجرا کنید (idempotent است) تا مدل‌ها و سرویس‌های جانبی هم
تازه شوند.

## راه‌اندازی دستی / توسعه

```bash
git clone https://github.com/mmahdi-sz/rostam.git && cd rostam
cp .env.example .env          # BOT_TOKEN را پر کن
cargo build                   # بیلد دیباگ (به files/runtime/libvosk.so نیاز دارد)
./target/debug/ros-telegram-bot
```

دستور `cargo build` به `files/runtime/libvosk.so` لینک می‌شود (به `build.rs` نگاه
کنید)، پس اسِت‌های مدل/رانتایم باید موجود باشند — یک‌بار `install.sh` را اجرا کنید
تا آن‌ها را بگیرد، یا دستی قرارشان دهید.

## کاستی‌های شناخته‌شده

- **دیمِن `surge` (پورت ۱۷۰۰)** از [SurgeDM/Surge](https://github.com/SurgeDM/Surge)
  نصب می‌شود و ربات را با یک فایل توکنِ متعلق به روت
  (`/root/.local/state/surge/token`) احراز هویت می‌کند. برای همین هم دیمِن و هم ربات
  با کاربر **root** اجرا می‌شوند تا آن توکن را مشترک داشته باشند — اجرای ربات با
  کاربر غیرروت باعث می‌شود `tools:surge` خطای ۴۰۱ بدهد.
- **cookie-pool فایرفاکس** به یک X display نیاز دارد؛ روی سرور بدون گرافیک،
  رفرش‌کننده‌ی کوکی یوتیوب اجرا نمی‌شود (یوتیوب بدون کوکی هم کار می‌کند). برای فعال
  کردنش `COOKIE_REFRESH_DISPLAY` را ست کنید / زیر Xvfb اجرا کنید.
- **باینری `deep-filter`** از ریلیزهای DeepFilterNet گرفته می‌شود؛ اگر آن فایل در
  دسترس نباشد، حذف نویزِ STT افت می‌کند (خودِ STT پایه همچنان کار می‌کند).
- **Bot API محلی** به `api_id`/`api_hash` تلگرام از
  <https://my.telegram.org> نیاز دارد؛ بدون آن، از `--skip-bot-api` استفاده کنید
  (API رسمی، سقف آپلود ۲۰ مگابایت).
