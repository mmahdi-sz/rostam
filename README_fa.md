# rostam — بات مدیا و ابزار تلگرام

[English](README.md) · **فارسی** · [Русский](README_ru.md)

یک بات چندزبانه‌ی تلگرام (Rust، کریت `ros-telegram-bot`، باینری `rostam-dev` در
dev و `rostam` در پروداکشن) — رابط کاربری به **فارسی، انگلیسی، ایتالیایی و روسی**
(تغییر با `/language`) — که یک جعبه‌ابزار مدیا را پشت یک رابط رنک‌بندی‌شده و
پی‌وال‌دار جمع می‌کند: دانلود یوتیوب، جداسازی صدا، تبدیل گفتار به متن، حذف نویز
صدا/ویدیو، تبدیل متن به گفتار، بزرگ‌نمایی تصویر، رنگی‌کردن عکس سیاه‌وسفید، حذف
پس‌زمینه، حذف واترمارک، فشرده‌سازی PDF و آرشیو، دانلود لینک مستقیم، لوکاپ IP و
پک‌های ایموجی سفارشی. بیشتر مدل‌ها **محلی** اجرا می‌شوند (ONNX با `ort`،
CTranslate2 با `ct2rs`، Vosk، Piper) و بقیه‌ی کار سنگین CPU در سرویس‌های کنار یا
پروسه‌های فرزند اجرا می‌شود که یک بروکر CPU مبتنی بر Redis آن‌ها را هماهنگ می‌کند.

نسخه‌ی فعلی: **2.1.2** (به [CHANGELOG.md](CHANGELOG.md) نگاه کنید — `Cargo.toml`
روی `0.1.0` می‌ماند؛ نسخه‌ی انتشار در تگ‌های گیت و چنج‌لاگ است).

## 🚀 شروع سریع (نصب‌کننده‌ی یک‌مرحله‌ای)

`install.sh` یک سرور خام Debian/Ubuntu یا Arch را از صفر تا صد راه می‌اندازد:
پکیج‌های سیستمی، Rust، deno، yt-dlp، حدود ۸ گیگابایت مدل، PostgreSQL + Redis،
بیلد release، همه‌ی سرویس‌های کنار و یونیت systemd به نام `rostam.service`.

```bash
sudo bash <(curl -Ls https://raw.githubusercontent.com/mmahdi-sz/rostam/master/install.sh)

# یا از یک چک‌اوت:
sudo bash install.sh --dir /opt/rostam --branch master
```

آپشن‌ها: `--dir`، `--branch`، `--skip-bot-api`، `--skip-firefox`، `--fresh`.
متغیرهای محیطی: `ROSTAM_REPO`، `ROSTAM_BRANCH`، `ROSTAM_ASSET_CACHE` (دایرکتوری
مدل‌های از قبل دانلود‌شده که بر اساس نام فایل پیدا می‌شوند — برای نصب مجدد یا
نصب آفلاین بدون دانلود دوباره‌ی ۸ گیگابایت).

ایمیج داکر وجود ندارد: کریت `files/runtime/libvosk.so` را با rpath در `build.rs`
لینک می‌کند، `migrations/` را در زمان کامپایل embed می‌کند و هفت پروسه‌ی
کنار/فرزند را می‌راند — کانتینر فقط کار اضافه می‌کند بدون این‌که چیزی کم کند.

## 🧪 تست و پایش

### اجرای سوئیت TestAPI و تست‌های یونیت
```bash
# ماتریس تست یونیت (۱۴۰ تست در ۳۷ ماژول).
# توجه: این کریت فقط باینری است — `cargo test --lib` چیزی پیدا نمی‌کند، از `cargo test` استفاده کنید.
cargo test

# سوئیت یکپارچگی TestAPI (۲۴ اندپوینت، هندلرهای واقعی + دیتابیس dev)
bash scripts/run_testapi_suite.sh
```

هر فیچر باید با یک اندپوینت `/test/<domain>/<action>` در `src/testapi/` بیاید (فقط
با `--features testapi` کامپایل می‌شود، به `127.0.0.1` بایند است، پورت از
`TESTAPI_PORT` با پیش‌فرض `14379`، با `TESTAPI_ENABLED=1` فعال) و در
`scripts/run_testapi_suite.sh` وایر شود. اندپوینت‌هایی که به دیتابیس دست می‌زنند
(`/test/quota`، `/test/redeem/apply`، `/test/referral/spend`) توابع **واقعی** را
روی دیتابیس dev با آی‌دی‌های یک‌بارمصرف در بازه‌ی `-999xxx` صدا می‌زنند.

### اندپوینت‌های Health و Metrics
- **Health:** `GET http://127.0.0.1:14380/health` (در dev برای جلوگیری از تصادم با
  پروداکشن `HEALTH_PORT=14381`)
- **متریک‌های Prometheus:** `GET http://127.0.0.1:14380/metrics`

## معماری

```

   Telegram  ─────────►│  local Bot API  :8081     │  (آپلود ۲ گیگ؛ prod :8082)

   realesrgan-ncnn-vulkan (بزرگ‌نمایی) · ffmpeg · ghostscript · 7z/rar · edge-tts
```

بات به Postgres، Redis و سرویس‌های کنار **تنبل (lazy)** وصل می‌شود — هیچ‌کدام در
زمان استارت لازم نیستند. اگر Postgres پایین باشد، بات بدون persistence بالا می‌آید
(و خطای خواندن سهمیه به کاربر می‌گوید با ادمین تماس بگیرد، به‌جای این‌که کار مجانی
بدهد — گیت سهمیه عمداً **fail-closed** است)؛ اگر یک سرویس کنار پایین باشد، فقط
همان فیچر «سرویس در دسترس نیست» برمی‌گرداند. تنها نیاز سخت استارت `BOT_TOKEN` است.

سنگین‌ترین بخش ML **درون‌پروسه** داخل باینری Rust اجرا می‌شود (بدون رفت‌وبرگشت
پایتون): اینپینتینگ واترمارک، رنگی‌کردن و حذف پس‌زمینه با ران‌تایم ONNX یعنی `ort`،
ترجمه‌ی زیرنویس با `ct2rs` (CTranslate2)، گفتار به متن با `vosk` و TTS فارسی با
`piper_rs`. جداسازی صدا و دانلود موازی مستقیم در سرویس‌های بیرونی هستند؛ حذف نویز،
بزرگ‌نمایی و فشرده‌سازی آرشیو و PDF به پروسه‌های فرزند سپرده می‌شوند. هر کار CPU
چندثانیه‌ای — درون‌پروسه، ساب‌پروسه یا سرویس کنار — از طریق **بروکر CPU**
(`127.0.0.1:6589`) زمان‌بندی می‌شود که کار را صف می‌کند و هسته‌های فیزیکی را با
Redis رزرو می‌کند تا تسک‌های همزمان سرور را نکشند.

**هیچ connection pool وجود ندارد**: `src/database/postgresql/mod.rs` یک
`Arc<Client>` تنها نگه می‌دارد و `tokio_postgres::Client::transaction()` به
`&mut self` نیاز دارد، پس کد از اساس صفر تراکنش SQL دارد. هر عملیات اتمیک (رزرو
سهمیه، مصرف کد هدیه، خرج امتیاز رفرال) به شکل **یک استیتمنت SQL** با
`ON CONFLICT` + `RETURNING` روی سطر قفل‌شده با کلید اصلی نوشته شده است. هرگز
`BEGIN`/`COMMIT` را از کلاینت مشترک نفرستید — استیتمنت‌های کاربران دیگر را می‌بلعد.

## قابلیت‌ها

**مدیا و هوش مصنوعی:** دانلود یوتیوب (ویدیو/پلی‌لیست/MP3 با پی‌وال کیفیت، زیرنویس و
ترافیک) · جداسازی وکال/موسیقی · گفتار به متن (Vosk) · حذف نویز صدا **و ویدیو**
(DeepFilterNet 3) · متن به گفتار (Piper فارسی / edge-tts انگلیسی) · بزرگ‌نمایی
تصویر (Real-ESRGAN، عکس + انیمه) · رنگی‌کردن عکس سیاه‌وسفید (DeOldify) · حذف
پس‌زمینه (PNG شفاف) · حذف واترمارک (Moebius ONNX، درون‌پروسه) · ترجمه‌ی زیرنویس (NLLB).

**فایل و لینک:** فشرده‌سازی PDF (Ghostscript) · فشرده‌سازی آرشیو (ZIP / 7Z / RAR،
LZMA2 / PPMd / BZip2، سطح ۰–۹، تقسیم ۵ مگ تا ۲ گیگ، رمز) · دانلود موازی سریع لینک
مستقیم (Surge) · تشخیص لینک پلتفرم‌های اجتماعی (`detect_social_platform`: تلگرام،
اینستاگرام، تیک‌تاک، توییتر، پینترست، فیسبوک، تردز، ساندکلاد، اسپاتیفای، آپارات،
روبیکا، ایتا) که لینک‌های یوتیوب خودکار به مسیر یوتیوب می‌روند.

**پلتفرم:** رنک و پی‌وال · سهمیه‌های پنجره‌ای با رزرو قبل از کار · رفرال +
لیدربورد · کدهای هدیه/ریدیم · گیت جوین اجباری · پک‌های ایموجی سفارشی · لوکاپ IP ·
پنل ادمین آمار/ترافیک/خطا · برودکست ادمین (کپی/فوروارد + پین، ۱۵ پیام در ثانیه،
تشخیص خودکار کاربران بلاک‌کننده).

دستورها: `/start`، `/panel`، `/language`، `/rank`، `/ref` (مستعار `/re`،
`/referral`)، به‌علاوه‌ی دستورهای ادمین برای کوکی‌پول. بقیه همه کالبک اینلاین به
شکل `{domain}:{action}:{args}` هستند.

## پایپ‌لاین هوش مصنوعی و یادگیری ماشین

همه‌ی مدل‌ها **محلی** اجرا می‌شوند — بدون API بیرونی، بدون هزینه‌ی هر فراخوانی،
بدون خروج داده از سرور. (تنها استثنا TTS انگلیسی است که از CLI `edge-tts`
مایکروسافت استفاده می‌کند.)

| توانایی | مدل / موتور | محل اجرا |
|---|---|---|
| **ترجمه‌ی زیرنویس** | **NLLB** متا با `ct2rs` (بایندینگ نیتیو CTranslate2) | درون‌پروسه |
| **گفتار به متن** | **Vosk** (فارسی + انگلیسی، مدل کوچک و بزرگ) | درون‌پروسه (`libvosk.so`) |
| **حذف نویز صدا/ویدیو** | **DeepFilterNet 3** (`files/runtime/deep-filter`) | ساب‌پروسه |
| **بزرگ‌نمایی تصویر** | **Real-ESRGAN** (ncnn-vulkan): مدل عکس + انیمه (x2/x3/x4) | ساب‌پروسه |
| **حذف واترمارک** | اینپینتینگ ONNX **Moebius** (کریت `ort`) | درون‌پروسه |
| **رنگی‌کردن** | **DeOldify** ONNX | درون‌پروسه (`ort`) |
| **حذف پس‌زمینه** | سگمنتیشن ONNX → PNG شفاف | درون‌پروسه (`ort`) |
| **متن به گفتار (fa)** | **Piper** `fa_IR-mantatts-par.onnx` با `piper_rs`، فرانت‌اند HomoFast eSpeak G2P + رفع ابهام هوموگراف | درون‌پروسه |
| **متن به گفتار (en)** | `edge-tts` (`en-US-AvaNeural`) | ساب‌پروسه |

- **ترجمه‌ی زیرنویس** — وقتی ویدیو زیرنویس فارسی ندارد، بات SRT انگلیسی را می‌گیرد،
  از مترجم محلی NLLB (`src/youtube/translator/`) عبور می‌دهد و `translated_fa.srt`
  را با حفظ تایمینگ اصلی بیرون می‌دهد.
- **STT** — زبان و اندازه‌ی مدل از کیبورد اینلاین انتخاب می‌شود. مدل‌های بزرگ
  («دقیق») پی‌وال دارند، کوچک‌ها آزادند. یک پاس اختیاری حذف نویز DeepFilterNet را
  می‌توان قبل از رونویسی روشن کرد.
- **بزرگ‌نمایی** — حالت عکس به‌علاوه‌ی یک تاگل مخصوص **انیمه** که
  `realesrgan-x4plus-anime` و `realesr-animevideov3` را روی x2/x3/x4 نشان می‌دهد.
- **TTS** — نوار پیشرفت زنده (درصد / زمان سپری‌شده / ETA)؛ اگر تنظیمات حریم خصوصی
  کاربر ویس را ببندد، به سند صوتی برمی‌گردد. کلون صدا در ۲.۱.۰ حذف شد.
- **حذف نویز** — روی ویس/صدا **و** MP4/MKV/WebM کار می‌کند (تِرَک صدا استخراج،
  نویزگیری و با ffmpeg دوباره remux می‌شود) با نوار پیشرفت و ETA زنده.

## یوتیوب — قابلیت‌های پیشرفته

- **تشخیص خودکار پلی‌لیست** — لینک پلی‌لیست باز می‌شود (`--flat-playlist`)، کاربر
  **یک‌بار** کیفیت را انتخاب می‌کند، بعد همه‌ی آیتم‌ها در یک حلقه با یک پیام وضعیت
  پین‌شده دانلود می‌شوند؛ خطای هر آیتم گزارش می‌شود بدون این‌که بَچ لغو شود.
- **انتخاب کیفیت و کدک** — رزولوشن، کدک ویدیو، زبان صدا و کیفیت فقط-صدا
  (بهترین / 128k / 64k) همه از یک پنل اینلاین انتخاب می‌شوند.
- **زیرنویس نرم** — زیرنویس امبد به شکل `mov_text` با `displayFlags=0` نوشته می‌شود
  تا پلیرها ترک را فقط *لیست* کنند نه اجباری نشان دهند. بعد از دانلود امبد، بات ۴
  بایت را درجا پچ می‌کند (اولین tx3g فعال → `0xC0000000`) تا VLC و بقیه درست رفتار
  کنند، بدون remux — و از `-c copy` جان سالم می‌برد.
- **دو حالت زیرنویس** — دانلود به‌عنوان **فایل** `.srt` جدا، یا **امبد** در کانتینر.
- **فقط صدا MP3** — `--extract-audio --audio-format mp3 -q 0` با نام فایل هوشمند و
  کپشن متادیتا.
- **حل چالش JS** — به yt-dlp یک ران‌تایم `deno` داده می‌شود (`--js-runtimes`) تا
  چالش‌های پلیر یوتیوب حل شود (بدون آن فقط storyboard می‌گیرید).

## کوکی‌پول و سیستم ضد‌بن

یوتیوب سخت ریت‌لیمیت و IP-بن می‌کند؛ کوکی‌پول بار را روی چند لاگین گوگل پخش می‌کند
تا هیچ اکانتی تنها نسوزد.

- **چرخش** — هر درخواست کوکی بعدی موجود را از استخری از پروفایل‌های فایرفاکس
  (`cookies.sqlite`) به‌صورت round-robin برمی‌دارد و آخرین کوکی مصرف‌شده در Postgres
  ذخیره می‌شود.
- **کول‌داون** — کوکی‌ای که `429` بخورد در یک جدول کول‌داون پارک می‌شود
  (`cookie_pool_cooldowns`، Postgres + حافظه) و تا پایان پنجره‌اش رد می‌شود؛ حلقه‌ی
  اصلی خودش آن را برمی‌گرداند.
- **ریفرش خودکار** — یک تسک پس‌زمینه (`spawn_cookie_refresher`، پیش‌فرض هر ۶۰۰
  ثانیه) یک پروفایل واقعی فایرفاکس را می‌راند تا سشن گوگل — و در نتیجه کوکی‌ها —
  تازه بماند.
- **عملیات دستی** — `/cookie_status`، `/cookie_next`، `/cookie_429` استخر را دستی
  بررسی و هدایت می‌کنند.
- **تلاش مجدد روی کوکی سوخته** — وقتی yt-dlp به‌خاطر `database is locked`،
  `The page needs to be reloaded` یا چالش تشخیص بات صفر فرمت برمی‌گرداند، خودکار
  کوکی بعدی امتحان می‌شود، به‌جای گزارش «کیفیت قابل دانلودی پیدا نشد».
- **تمام شدن استخر** — اگر همه‌ی پروفایل‌ها ناموجود باشند، کاربر پیام روشن
  «موقتاً در دسترس نیست» می‌گیرد (کول‌داون امنیتی **۱ ساعت**، ریفرش می‌تواند زودتر
  آزاد کند) و ادمین یک هشدار تشخیصی کوکی/جیمیل می‌گیرد، حداکثر یکی هر ۳۰ دقیقه.

وضعیت با سه جدول از ری‌استارت جان سالم می‌برد: `cookie_pool_cookies`،
`cookie_pool_state`، `cookie_pool_cooldowns`.

## بروکر CPU و صف کار

هر تسک CPU چندثانیه‌ای از یک **بروکر مبتنی بر Redis** رد می‌شود که سرویس
separation روی **`127.0.0.1:6589`** میزبانش است. مصرف‌کننده‌های امروز: بزرگ‌نمایی،
واترمارک (Moebius)، رنگی‌کردن، حذف پس‌زمینه، TTS، فشرده‌سازی PDF، فشرده‌سازی آرشیو،
پست‌پروسس یوتیوب و دانلودهای Surge.

- `POST /cpu/acquire` مجموعه‌ای از هسته‌های فیزیکی را برای فراخوان رزرو می‌کند؛ تسک
  پین‌شده روی آن‌ها اجرا و در پایان آزاد می‌شود.
- `GET /cpu/status` هسته‌های آزاد، طول صف و فلگ `overloaded` را می‌دهد تا بات بتواند
  به کاربر بگوید «سیستم مشغول است، در صف» به‌جای کشتن سرور.
- کار **صف** می‌شود نه دراپ — فراخوان‌ها نوبت می‌گیرند (تایم‌اوت separation ۴۰ دقیقه
  است تا صف + پردازش را پوشش دهد).

## رنک، پی‌وال و سهمیه

پنج رنک صعودی: **دلاور** (رایگان) → **سپهبد** → **اسفندیار** → **سهراب** → **رستم**.

- رنک مؤثر روی هر کلیک گیت‌شده **زنده** خوانده می‌شود (`rank::effective_rank`) —
  هیچ‌وقت کش نمی‌شود — و با `user_ranks.expires_at` منقضی می‌شود. پنل رنک مؤثر زنده
  را نشان می‌دهد، رنک پولی منقضی‌شده را «منقضی شده» علامت می‌زند و زیر یک روز
  ساعت/دقیقه شمارش معکوس می‌کند.
- **دکمه‌ها همیشه دیده می‌شوند**؛ پی‌وال روی کلیک شلیک می‌کند تا رنک‌های پایین‌تر
  ببینند چه چیزی را از دست می‌دهند.
- گیت‌شده‌ها: کیفیت یوتیوب، زیرنویس یوتیوب، ترافیک یوتیوب (روزانه + ماهانه، تخمین از
  بیت‌ریت × مدت)، حذف نویز (روزانه + هفتگی)، STT (سریع/دقیق × روزانه/هفتگی)،
  جداسازی (روزانه + هفتگی)، بزرگ‌نمایی x2/x3/x4 هفتگی، TTS هفتگی، DeOldify هفتگی،
  حذف پس‌زمینه هفتگی، ثانیه‌های CPU فشرده‌سازی آرشیو (روزانه + ماهانه).
- سهمیه‌ها در `user_quotas` هستند (کلید اصلی `(user_id, quota_type)`، پنجره‌ی
  چرخشی از `window_start`).

### رزرو قبل از کار، برگشت روی خطا

سهمیه‌ها **از قبل رزرو** می‌شوند نه بعداً کسر. `rank::quota::reserve_usage` بررسی
سقف *و* افزایش را در **یک استیتمنت SQL** روی سطر قفل‌شده با `user_quotas_pkey`
انجام می‌دهد، پس دو درخواست همزمان نمی‌توانند هر دو از چک رد شوند. هر مسیر خطای
بین رزرو و تحویل `refund_usage` را صدا می‌زند.

- هندلرهای دو‌پنجره‌ای اول پنجره‌ی **کوتاه‌تر** را رزرو می‌کنند و اگر پنجره‌ی بلندتر
  رد کرد، همان‌جا برمی‌گردانند.
- مقدار صفر (شکست خواندن هدر WAV یا `ffprobe`) به **حداقل یک ثانیه** کلمپ می‌شود تا
  یک پروب خراب نتواند کار مجانی بخرد.
- خطای دیتابیس روی گیت **fail-closed** است: کاربر `rank.quota_db_error` می‌گیرد (در
  هر ۴ زبان) که می‌گوید با `@mmahdi_sz` تماس بگیرد.
- فشرده‌سازی آرشیو تنها استثنایی است که هنوز بعداً تسویه می‌شود — واحدش ثانیه‌ی CPU
  است که قبل از پایان کار قابل دانستن نیست، پس ۱ ثانیه رزرو می‌کند و باقی را در
  پایان اضافه می‌کند.
- `TrafficDaily`/`TrafficMonthly` هنوز پس از کار متر می‌شوند.

`/test/quota` همان توابع واقعی reserve/refund/get را روی دیتابیس dev اجرا می‌کند
(نوع شمارشی و نوع مقداری، رد شدن روی سقف، برگشت، جا شدن دقیق، و برگشت بزرگ‌تر از
مصرف).

## سیستم رفرال (ضد‌تقلب)

لینک دعوت: `https://t.me/{bot}?start={referrer_id}`.

- یک `/start` با پیلود عددی رفرال را **در انتظار** ثبت می‌کند (`referral_pending`) —
  فوراً امتیاز نمی‌دهد.
- یک جاروکش ساعتی (`sweep_confirm`) سطرهای در انتظار قدیمی‌تر از **`PENDING_DAYS`
  = ۲** را دوباره چک می‌کند: اگر مهمان هنوز عضو جوین اجباری باشد به `referrals`
  ارتقا می‌یابد (۱ امتیاز)؛ اگر رفته باشد سطر دور ریخته می‌شود. این حلقه‌ی تقلب
  «جوین شو → شمرده شو → لفت بده» را می‌کشد.
- امتیازها **خرج** می‌شوند تا یک رنک را برای **۳۱ روز** (`ACTIVATION_DAYS`) فعال
  کنند، با نردبان مخصوص رفرال (`TIERS`): سهراب ۱۰، اسفندیار ۲۰، رستم ۵۰. موجودی =
  `COUNT(referrals) − SUM(points_spent)`. دان‌گرید رد می‌شود. خرج یک استیتمنت
  ایدمپوتنت است (مایگریشن `V005`)، پس دو‌بار زدن نه دو‌بار می‌دهد نه موجودی را منفی
  می‌کند.
- **لیدربورد** — بهترین رفرال‌دهنده‌ها با 🥇/🥈/🥉، جوین‌شده با `stats_users` برای
  نام کاربری.
- **نکته‌ی مهم**: رفرال به قفل جوین اجباری نیاز دارد — بدون آن `is_joined()` همیشه
  true است و هر رفرال در انتظار خودکار تأیید می‌شود.

## کدهای هدیه / ریدیم

- ادمین‌ها کد را از پنل با فلگ‌ها به هر ترتیب می‌سازند: `30d es 1u` → ۳۰ روز، رنک
  اسفندیار، ۱ مصرف (`<n>d` روز، `<n>u` تعداد مصرف، مخفف رنک `da/se/es/so/ro`).
- کدها ۸ کاراکتر از یک الفبای بی‌ابهام هستند (بدون `0/O/1/I`) تا در دیپ‌لینک
  `?start=` تلگرام تمیز سوار شوند.
- **انقضای لغزان ۷ روزه**: کد با `now + 7d` متولد می‌شود؛ هر ریدیم پنجره را ریست
  می‌کند؛ بعد از انقضا جارو می‌شود (`spawn_redeem_sweeper`).
- `max_uses` سقف مصرف است؛ `redeem_redemptions` (کلید اصلی `code,user_id`) یک ریدیم
  به هر کاربر را تضمین می‌کند.

## سیستم جوین اجباری

یک گیت عضویت اجباری در کانال که بعد از انتخاب زبان و قبل از هر فیچر اجرا می‌شود:

- عضویت **در Redis کش می‌شود** تا گیت روی هر اکشن به API تلگرام فشار نیاورد.
- کش با **گوش دادن به آپدیت‌های `chat_member`** گرم نگه داشته می‌شود
  (`on_chat_member_update`) — لحظه‌ای که کاربر جوین یا لفت می‌دهد، Redis بدون هیچ
  فراخوان API اضافه آپدیت می‌شود.
- دکمه‌ی سبز «عضو شدم» یک چک **زنده** را اجبار می‌کند و کش را دور می‌زند.

جوین اجباری لنگر اعتماد تأیید رفرال هم هست (بالا را ببینید).

## پنل ادمین و مانیتورینگ

کالبک‌های فقط-ادمین (`admin:panel`)، گیت‌شده با `ADMIN_USER_ID`:

- **آمار** — شمار رویداد هر فیچر (`stats_events`) و شمار کاربران (`stats_users`).
- **ترافیک** — بایت دانلود/آپلود هر کاربر و موفقیت آپلود (`stats_downloads`)؛
  زمان اولین آپلود روی `stats_users` مهر می‌شود.
- **خطاها (۲۴ ساعت اخیر)** — هر خطای فیچر ثبت می‌شود (`stats_errors`، سقف ۵۰۰
  کاراکتر) و روی درخواست رندر می‌شود، پس می‌توانید از داخل تلگرام تریاژ کنید.
- **عملیات** — مدیریت قفل جوین اجباری و ساخت کد هدیه بدون خروج از چت.
- **برودکست** — ارسال به همه‌ی کاربران شناخته‌شده با `copy_message` یا
  `forward_message`، با پین اختیاری، throttle روی ۱۵ پیام در ثانیه (۶۷ میلی‌ثانیه
  تأخیر)؛ کاربرانی که بات را بلاک کرده‌اند خودکار `is_blocked = true` می‌شوند.

## لاگ trace

هر اکشن کاربر یک **trace id** دارد که از همه‌ی هلپرها رد می‌شود، پس `rg trace=N`
کل اکشن را به ترتیب بازپخش می‌کند. دو نوع خط:

```
[<domain> trace=N actor] user=@<u> id=<id> rank=<R> clicked=<cb>    # یک‌بار، در ورودی
[<domain> trace=N event=<step>] k=v => ok|fail err=..|pass|blocked  # هر مرحله، قبل از اجرا
```

نبودن یک خط event یعنی آن مرحله هرگز اجرا نشده — خودِ غیبت سیگنال است. رمزها
هرگز ظاهر نمی‌شوند: توکن بات قبل از رسیدن هر رشته‌ی خطا به journald،
`stats_errors` یا پنل خطای ادمین ریدکت می‌شود (خطاهای `frankenstein` کل URL
درخواست را — که توکن داخلش است — جا می‌دهند). آی‌دی‌ها به ۶ کاراکتر اول کوتاه می‌شوند.

نمونه (روی acquire شدن CPU شکست می‌خورد — `cores=[]` مدرک قاطع است):

```
[upscale trace=43 actor] user=@parsa id=671234… rank=Dalavar clicked=upscale:model:realesrgan-x4plus
[upscale trace=43 event=quota_check] used=2 limit=3 => pass
[upscale trace=43 event=cpu_acquire] => cores=[]
```

دنبال کردن: `journalctl -u rostam -n 300 | rg trace=` (در dev: `-u rostam_dev`).
ماکروها در `src/log.rs` هستند (`log_actor!`، `log_actor_id!`، `log_ev!`) — هرگز
`eprintln!` خام.

هندلرها با **`spawn_user_task`** اسپاون می‌شوند نه `tokio::spawn` خالی:
`tokio::task_local!` از مرز spawn عبور نمی‌کند، پس spawn خام زبان کاربر را گم
می‌کرد (بی‌صدا فارسی سرو می‌کرد) و گارد drain خاموشی را می‌انداخت. فقط اسپاون‌های
دیمن بلندعمر در `src/app/startup.rs` خام می‌مانند — تبدیل آن‌ها نمی‌گذاشت drain
هرگز به صفر برسد.

## پیکربندی (`.env`)

نصب‌کننده `.env` را از `.env.example` می‌سازد. مقادیر کلیدی:

| متغیر | کاربرد |
|---|---|
| `BOT_TOKEN` | **الزامی** — از @BotFather |
| `ADMIN_USER_ID` | آی‌دی تلگرام با دسترسی پنل ادمین + کش ایموجی |
| `DATABASE_URL` | `postgres://postgres:postgres@localhost:5432/ros_telegram_bot` (prod: `..._production`) |
| `REDIS_URL` | پیش‌فرض `redis://127.0.0.1:6379` |
| `BOT_API_BASE_URL` | `http://127.0.0.1:8081` (prod `:8082`؛ خالی → API رسمی، سقف ۲۰ مگ) |
| `HEALTH_PORT` | پورت health + metrics، پیش‌فرض `14380`؛ **dev باید `14381` باشد** |
| `TESTAPI_ENABLED` / `TESTAPI_PORT` | فعال‌سازی تست API محلی (`1`) و پورتش (پیش‌فرض `14379`) — نیازمند `--features testapi` |
| `COOKIE_REFRESH_ENABLED` | در dev `false`، در prod `true` |
| `SEP_BIND_HOST` | آدرس بایند separation-service؛ پیش‌فرض `127.0.0.1`، فقط داخل کانتینر تغییرش دهید |
| `DENO_PATH` | مسیر باینری deno (پیش‌فرض `/opt/deno/bin/deno`) |
| `IPINFO_TOKEN`، `ABUSEIPDB_KEY` | غنی‌سازی اختیاری لوکاپ IP |

قیمت رنک‌ها و `buy_url` (که فعلاً بی‌اثر است) در `config/config.yml` هستند؛ رشته‌های
کاربری در `config/i18n.json` برای هر چهار زبان و با `i18n::reload()` در ران‌تایم
قابل بارگذاری مجدد.

همه‌ی مسیرهای فیچرها (`files/models/*`، `models/piper/*`، `config/i18n.json`) نسبت
به **دایرکتوری کاری بات** حل می‌شوند، پس یونیت systemd باید `WorkingDirectory` را
درست تنظیم کند.

`cargo build` به `files/runtime/libvosk.so` لینک می‌کند (به `build.rs` نگاه کنید)،
پس فایل‌های مدل/ران‌تایم باید موجود باشند — یک‌بار `install.sh` را اجرا کنید یا
دستی جاگذاری کنید.

## شکاف‌های شناخته‌شده

- **خرید رنک کاملاً دستی است.** `buy_url` در `config/config.yml` بی‌اثر است و هیچ کد
  پرداختی وجود ندارد؛ صفحه‌ی فروشگاه به ادمین لینک می‌دهد. این عمدی است.
- **`separation-service` احراز هویت اندپوینت ندارد.** روی لوپ‌بک بایند است
  (`127.0.0.1:6589`) که در معرض بودن را می‌بندد نه احراز هویت را — ۹ ریکوئست‌بیلدر
  Rust و ۵ ثابت تکراری `SEP_BASE` باید عوض شوند.
- **`rostam.service` (پروداکشن) هنوز روت اجرا می‌شود**، همراه با فایل‌های متعلق به
  روت زیر `production/`. یونیت dev سخت‌سازی شده؛ پروداکشن عمداً دست‌نخورده مانده.
  دستور کار در [plans/README.md](plans/README.md).
- **دیمن `surge` (پورت ۱۷۰۰)** بات را با یک فایل توکن متعلق به روت احراز می‌کند
  (`/root/.local/state/surge/token`)؛ اگر بات با کاربر غیرروت و بدون دسترسی به آن
  اجرا شود، `tools:surge` خطای 401 می‌دهد.
- **drain خاموشی ۳۰ ثانیه‌ای** (`src/app/mod.rs`) کوتاه‌تر از کارهای واقعی است — یک
  STT ده‌دقیقه‌ای همچنان قطع می‌شود.
- **مپ‌های فلگ لغو به‌جای رد کردن، بازنویسی می‌کنند** (`ACTIVE_STT_JOBS`،
  `ACTIVE_DENOISE_JOBS`، `register_upscale`)، پس کار همزمان دوم یک کاربر فلگ لغو
  اولی را یتیم می‌کند و «لغو» فقط جدیدترین کار را لغو می‌کند.
- **اندپوینت‌های testapi هوش مصنوعی ماک هستند** (`/test/stt/recognize`،
  `/test/separation/submit`، `/test/gwm/detect`، `/test/denoise/process`،
  `/test/tts/generate`، `/test/deoldify/colorized`، `/test/nobg/process`) — پاسخ
  آماده می‌سازند به‌جای راندن هندلر، چون به فایل نمونه‌ی مدیا + ONNX نیاز دارد.
- **کوکی‌پول فایرفاکس** به یک نمایشگر X نیاز دارد؛ روی سرور بدون مانیتور ریفرشر
  کوکی یوتیوب اجرا نمی‌شود (یوتیوب بدون کوکی هم کار می‌کند). با
  `COOKIE_REFRESH_DISPLAY` یا اجرا زیر Xvfb فعالش کنید.
- **باینری `deep-filter`** از ریلیزهای DeepFilterNet گرفته می‌شود؛ اگر آن فایل در
  دسترس نباشد، حذف نویز و نویزگیری STT تنزل می‌کنند (خود STT پایه کار می‌کند).
- **Bot API محلی** به `api_id`/`api_hash` تلگرام از <https://my.telegram.org> نیاز
  دارد؛ بدون آن از `--skip-bot-api` استفاده کنید (API رسمی، سقف آپلود ۲۰ مگابایت).
