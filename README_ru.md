# rostam — Telegram-бот для медиа и утилит

[English](README.md) · [فارسی](README_fa.md) · **Русский**

Многоязычный Telegram-бот (Rust, крейт `ros-telegram-bot`, бинарь `rostam-dev`
в dev / `rostam` в production) — интерфейс на **персидском, английском,
итальянском и русском** (переключение через `/language`) — собирающий медиа-набор
за платным ранговым интерфейсом: загрузка с YouTube, разделение вокала,
речь-в-текст, шумоподавление аудио/видео, синтез речи, апскейл изображений,
раскрашивание Ч/Б фото, удаление фона, удаление водяных знаков, сжатие PDF и
архивов, загрузка по прямым ссылкам, IP-lookup, наборы кастомных эмодзи. Почти
весь ML работает **локально** (ONNX через `ort`, CTranslate2 через `ct2rs`, Vosk,
Piper); остальная тяжёлая CPU-работа идёт в сайдкар-сервисах или дочерних
процессах, которых координирует CPU-брокер на Redis.

Текущий релиз: **2.1.2** (см. [CHANGELOG.md](CHANGELOG.md) — `Cargo.toml`
остаётся на `0.1.0`, версия релиза живёт в git-тегах и changelog).

## 🚀 Быстрый старт (установщик в одну команду)

`install.sh` поднимает чистый хост Debian/Ubuntu или Arch от начала до конца:
системные пакеты, Rust, deno, yt-dlp, ~8 ГБ моделей, PostgreSQL + Redis,
release-сборка, все сайдкары и systemd-юнит `rostam.service`.

```bash
sudo bash <(curl -Ls https://raw.githubusercontent.com/mmahdi-sz/rostam/master/install.sh)

# или из чекаута:
sudo bash install.sh --dir /opt/rostam --branch master
```

Опции: `--dir`, `--branch`, `--skip-bot-api`, `--skip-firefox`, `--fresh`.
Переменные: `ROSTAM_REPO`, `ROSTAM_BRANCH`, `ROSTAM_ASSET_CACHE` (каталог уже
скачанных моделей, поиск по имени файла — позволяет переустановить или
развернуть офлайн без повторной загрузки ~8 ГБ).

Docker-образа нет: крейт линкует `files/runtime/libvosk.so` через rpath в
`build.rs`, встраивает `migrations/` на этапе компиляции и управляет семью
сайдкар/дочерними процессами — контейнер добавляет работу, ничего не убирая.

У `files/models/deoldify/ddcolor_modelscope.onnx` (980 МБ) нет HTTP-зеркала —
установщик выцепляет confirm-токен Google Drive, скачивает архив
`ddcolorizer_onnx_models.zip` на 1,9 ГБ, извлекает только этот файл и проверяет

`rar` лежит в компоненте `non-free` Debian, поэтому перед `apt-get update`
установщик включает `contrib non-free non-free-firmware` в существующих сюитах
Debian/Ubuntu (и формат deb822 `.sources`, и старый однострочный `sources.list`).

## Архитектура

```
                       ┌──────────────────────────┐
   Telegram  ─────────►│  local Bot API  :8081     │  (загрузка 2 ГБ; prod :8082)
                       └────────────┬─────────────┘
                                    │
                          ┌─────────▼─────────┐        ┌───────────────────┐
                          │  rostam (Rust)    │───────►│  in-process ML     │
                          │  target/release/  │        │  ort (Moebius,     │
                          │     rostam        │        │   DeOldify, nobg)  │
                          └───┬───────┬───┬───┘        │  ct2rs (NLLB)      │
             ┌────────────────┘       │   └───────┐    │  vosk (STT)        │
             │                        │           │    │  piper_rs (fa TTS) │
      ┌──────▼──────┐          ┌──────▼──────┐  ┌─▼────────────┐ └─────────┘
      │ PostgreSQL  │          │   Redis     │  │  Firefox     │
      │  :5432      │          │   :6379     │  │  cookie pool │
      └─────────────┘          └──────┬──────┘  └──────────────┘
                                      │
                          ┌───────────┴───────────┐
                          │      CPU broker        │  (очередь + резерв ядер,
                          │  127.0.0.1:6589        │   на Redis)
                          └───────────┬───────────┘
                            ┌─────────┴─────────┐
                    ┌───────▼────┐      ┌───────▼────┐
                    │ separation │      │  surge dl  │
                    │   :6589    │      │   :1700    │
                    └────────────┘      └────────────┘

   дочерние процессы (не сайдкары): deep-filter (шумоподавление) ·
   realesrgan-ncnn-vulkan (апскейл) · ffmpeg · ghostscript · 7z/rar · edge-tts
```

Бот подключается к Postgres, Redis и сайдкарам **лениво** — ни один не нужен на
старте. Если Postgres лежит, бот работает без персистентности (а ошибка чтения
квоты просит пользователя написать админу, вместо того чтобы отдать работу
бесплатно — квотный гейт намеренно **fail-closed**); если лежит сайдкар, только
его фича возвращает «сервис недоступен». Единственное жёсткое требование при
старте — `BOT_TOKEN`.

Самый тяжёлый ML работает **внутри процесса** Rust-бинаря (без похода в Python):
инпейнтинг водяных знаков, раскрашивание и удаление фона через ONNX-рантайм
`ort`, перевод субтитров через `ct2rs` (CTranslate2), речь-в-текст через `vosk`,
персидский TTS через `piper_rs`. Разделение вокала и параллельные прямые загрузки
живут во внешних сайдкарах; шумоподавление, апскейл, сжатие архивов и PDF уходят
в дочерние процессы. Любая многосекундная CPU-задача — внутрипроцессная,
подпроцесс или сайдкар — планируется через **CPU-брокер** (`127.0.0.1:6589`),
который ставит работу в очередь и резервирует физические ядра через Redis, чтобы
параллельные задачи не забили машину.

**Пула соединений нет**: `src/database/postgresql/mod.rs` держит единственный
`Arc<Client>`, а `tokio_postgres::Client::transaction()` требует `&mut self`, так
что в коде по построению ноль SQL-транзакций. Каждая атомарная операция (резерв
квоты, списание кода, трата реферальных очков) выражена **одним SQL-запросом** с
`ON CONFLICT` + `RETURNING` по строке, залоченной первичным ключом. Никогда не
отправляйте `BEGIN`/`COMMIT` через общий клиент — это проглотит запросы других
пользователей.

## Возможности

**Медиа и AI:** загрузка с YouTube (видео/плейлист/MP3, платные ограничения по
качеству, субтитрам и трафику) · разделение вокал/минус · речь-в-текст (Vosk) ·
шумоподавление аудио **и видео** (DeepFilterNet 3) · синтез речи (Piper fa /
edge-tts en) · апскейл изображений (Real-ESRGAN, фото + аниме) · раскрашивание
Ч/Б фото (DeOldify) · удаление фона (прозрачный PNG) · удаление водяных знаков
(Moebius ONNX, в процессе) · перевод субтитров (NLLB).

**Файлы и ссылки:** сжатие PDF (Ghostscript) · сжатие архивов (ZIP / 7Z / RAR,
LZMA2 / PPMd / BZip2, уровни 0–9, разбиение 5 МБ – 2 ГБ, пароль) · быстрая
параллельная загрузка по прямым ссылкам (Surge) · распознавание ссылок соцсетей
(`detect_social_platform`: telegram, instagram, tiktok, twitter, pinterest,
facebook, threads, soundcloud, spotify, aparat, rubika, eitaa), причём ссылки
YouTube автоматически уходят в YouTube-поток.

**Платформа:** ранги и paywall · оконные квоты с резервом до работы · реферальная
программа + лидерборд · подарочные коды · обязательная подписка на канал ·
наборы кастомных эмодзи · IP-lookup · админ-панель статистики/трафика/ошибок ·
админ-рассылка (copy/forward + пин, 15 сообщений/с, автоопределение
заблокировавших бота).

Команды: `/start`, `/panel`, `/language`, `/rank`, `/ref` (алиасы `/re`,
`/referral`) плюс админские команды cookie-пула. Всё остальное — инлайн-колбэки
в форме `{domain}:{action}:{args}`.

## AI / ML-конвейер

Все модели работают **локально** — без внешнего AI API, без оплаты за вызов, без
утечки данных с машины. (Единственное исключение — английский TTS, использующий
CLI `edge-tts` от Microsoft.)

| Возможность | Модель / движок | Где работает |
|---|---|---|
| **Перевод субтитров** | **NLLB** от Meta через `ct2rs` (нативный биндинг CTranslate2) | в процессе |
| **Речь-в-текст** | **Vosk** (персидский + английский, малые и большие модели) | в процессе (`libvosk.so`) |
| **Шумоподавление аудио/видео** | **DeepFilterNet 3** (`files/runtime/deep-filter`) | подпроцесс |
| **Апскейл изображений** | **Real-ESRGAN** (ncnn-vulkan): фото + аниме (x2/x3/x4) | подпроцесс |
| **Удаление водяных знаков** | ONNX-инпейнтинг **Moebius** (крейт `ort`) | в процессе |
| **Раскрашивание** | **DeOldify** ONNX | в процессе (`ort`) |
| **Удаление фона** | ONNX-сегментация → прозрачный PNG | в процессе (`ort`) |
| **Синтез речи (fa)** | **Piper** `fa_IR-mantatts-par.onnx` через `piper_rs`, фронтенд HomoFast eSpeak G2P + разрешение омографов | в процессе |
| **Синтез речи (en)** | `edge-tts` (`en-US-AvaNeural`) | подпроцесс |

- **Перевод субтитров** — если у видео нет персидских субтитров, бот берёт
  английский SRT, прогоняет через локальный NLLB (`src/youtube/translator/`) и
  выдаёт `translated_fa.srt` с сохранением исходного тайминга.
- **STT** — язык и размер модели выбираются инлайн-клавиатурой. Большие
  («точные») модели платные, малые бесплатны. Перед распознаванием можно включить
  необязательный проход DeepFilterNet.
- **Апскейл** — режим фото плюс отдельный переключатель **Аниме**, открывающий
  `realesrgan-x4plus-anime` и `realesr-animevideov3` на x2/x3/x4.
- **TTS** — живой прогресс-бар (процент / прошло / ETA); откатывается на
  аудио-документ, если приватность пользователя запрещает голосовые. Клонирование
  голоса удалено в 2.1.0.
- **Шумоподавление** — работает с голосовыми/аудио **и** MP4/MKV/WebM (аудиотрек
  извлекается, чистится и ремуксится через ffmpeg) с живым ETA.

## YouTube — продвинутые функции

- **Автоопределение плейлиста** — ссылка на плейлист раскрывается
  (`--flat-playlist`), пользователь выбирает качество **один раз**, затем все
  элементы качаются в цикле с закреплённым живым статусом; ошибки отдельных
  элементов сообщаются без прерывания пачки.
- **Выбор качества и кодека** — разрешение, видеокодек, язык аудио и качество
  только-аудио (лучшее / 128k / 64k) выбираются на одной инлайн-панели.
- **Мягкие субтитры** — встроенные субтитры пишутся как `mov_text` с
  `displayFlags=0`, чтобы плееры *показывали* дорожку в списке, но не включали её
  принудительно. После встраивания бот патчит 4 байта на месте (первый включённый
  tx3g → `0xC0000000`), чтобы VLC и прочие вели себя корректно, без ремукса — это
  выживает `-c copy`.
- **Два режима субтитров** — отдельным файлом `.srt` или **встраиванием** в
  контейнер.
- **Только аудио MP3** — `--extract-audio --audio-format mp3 -q 0`, с умным
  именем файла и подписью из метаданных.
- **Решение JS-челленджей** — yt-dlp получает рантайм `deno` (`--js-runtimes`),
  чтобы челленджи плеера YouTube решались (без него получите только storyboard).

## Cookie-пул и защита от бана

YouTube агрессивно ограничивает и банит по IP; cookie-пул распределяет нагрузку
по множеству Google-аккаунтов, чтобы не сгорел один.

- **Ротация** — каждый запрос берёт следующую доступную cookie из пула
  Firefox-профилей (`cookies.sqlite`), по кругу, с сохранением последней
  использованной в Postgres.
- **Кулдаун** — получившая `429` cookie парикуется в таблицу кулдаунов
  (`cookie_pool_cooldowns`, Postgres + память) и пропускается до истечения окна;
  основной цикл возвращает её автоматически.
- **Автообновление** — фоновая задача (`spawn_cookie_refresher`, по умолчанию
  каждые 600 с) управляет реальным профилем Firefox, чтобы Google-сессия — а
  значит и cookies — оставалась свежей.
- **Ручные операции** — `/cookie_status`, `/cookie_next`, `/cookie_429`.
- **Повтор на испорченной cookie** — когда yt-dlp возвращает ноль форматов из-за
  `database is locked`, `The page needs to be reloaded` или челленджа
  антибот-защиты, автоматически пробуется следующая cookie вместо сообщения «нет
  доступного качества».
- **Исчерпание пула** — если недоступны все профили, пользователь получает
  понятное сообщение о временной недоступности (страховочный кулдаун **1 час**,
  обновление может освободить раньше), а админ — диагностику cookie/Gmail, не
  чаще одной в 30 минут.

Состояние переживает перезапуск в трёх таблицах: `cookie_pool_cookies`,
`cookie_pool_state`, `cookie_pool_cooldowns`.

## CPU-брокер и очередь задач

Любая многосекундная CPU-задача проходит через **брокер на Redis**, который
хостит separation-сервис на **`127.0.0.1:6589`**. Сегодняшние потребители:
апскейл, водяные знаки (Moebius), раскрашивание, удаление фона, TTS, сжатие PDF,
сжатие архивов, постобработка YouTube и загрузки Surge.

- `POST /cpu/acquire` резервирует набор физических ядер для вызывающего; задача
  выполняется закреплённой на них и освобождает их по завершении.
- `GET /cpu/status` отдаёт свободные ядра, длину очереди и флаг `overloaded`,
  чтобы бот мог сказать «система занята, в очереди» вместо перегрузки машины.
- Работа **ставится в очередь**, а не отбрасывается — вызывающие ждут своей
  очереди (таймаут separation 40 минут, чтобы покрыть очередь + обработку).

## Ранги, paywall и квоты

Пять рангов по возрастанию: **Dalavar** (бесплатный) → **Sepahbod** →
**Esfandyar** → **Sohrab** → **Rostam**.

- Действующий ранг читается **живьём** на каждом платном клике
  (`rank::effective_rank`) — никогда не кешируется — и истекает через
  `user_ranks.expires_at`. Панель показывает живой ранг, помечает истёкший платный
  как «منقضی شده» и ведёт отсчёт в часах/минутах, если осталось меньше суток.
- **Кнопки видны всегда**; paywall срабатывает при клике, чтобы низкие ранги
  видели, чего лишаются.
- Ограничено: качество YouTube, субтитры YouTube, трафик YouTube (в день + в
  месяц, оценка по битрейту × длительности), шумоподавление (день + неделя), STT
  (быстро/точно × день/неделя), разделение (день + неделя), апскейл x2/x3/x4 в
  неделю, TTS в неделю, DeOldify в неделю, удаление фона в неделю, CPU-секунды
  сжатия архивов (день + месяц).
- Квоты живут в `user_quotas` (PK `(user_id, quota_type)`, скользящее окно от
  `window_start`).

### Резерв до работы, возврат при ошибке

Квоты **резервируются заранее**, а не списываются после.
`rank::quota::reserve_usage` делает проверку лимита *и* инкремент **одним
SQL-запросом** по строке, залоченной `user_quotas_pkey`, поэтому два
одновременных запроса не могут оба пройти проверку. Каждый путь ошибки между
резервом и выдачей вызывает `refund_usage`.

- Двухоконные хендлеры резервируют сначала **короткое** окно и возвращают его
  сразу, если длинное отклонило.
- Нулевая величина (сбой чтения WAV-заголовка или `ffprobe`) зажимается до
  **минимум одной секунды**, чтобы сломанный пробник не купил бесплатную работу.
- Ошибка БД на гейте **fail-closed**: пользователь получает
  `rank.quota_db_error` (на всех 4 языках) с просьбой написать `@mmahdi_sz`.
- Сжатие архивов — единственное исключение, которое всё ещё рассчитывается
  постфактум: его единица — CPU-секунды, неизвестные до конца задачи, поэтому
  резервируется 1 секунда, а остаток добавляется по завершении.
- `TrafficDaily`/`TrafficMonthly` по-прежнему считаются постфактум.

`/test/quota` прогоняет реальные функции reserve/refund/get на dev-базе
(счётчик и величина, отказ при лимите, возврат, точное попадание, возврат больше
использованного).

## Реферальная система (антифрод)

Ссылка-приглашение: `https://t.me/{bot}?start={referrer_id}`.

- `/start` с числовым payload записывает **ожидающий** реферал
  (`referral_pending`) — очки сразу не начисляются.
- Часовой свипер (`sweep_confirm`) перепроверяет ожидающие строки старше
  **`PENDING_DAYS` = 2**: если приглашённый всё ещё подписан на обязательный
  канал, строка повышается в `referrals` (1 очко); если ушёл — отбрасывается. Это
  убивает схему «подписался → зачли → ушёл».
- Очки **тратятся** на активацию ранга на **31 день** (`ACTIVATION_DAYS`) по
  отдельной реферальной лестнице (`TIERS`): Sohrab = 10, Esfandyar = 20,
  Rostam = 50. Баланс = `COUNT(referrals) − SUM(points_spent)`. Понижение
  отклоняется. Трата — один идемпотентный запрос (миграция `V005`), поэтому
  двойное нажатие не выдаст дважды и не уведёт баланс в минус.
- **Лидерборд** — топ рефереров с 🥇/🥈/🥉, join со `stats_users` за юзернеймами.
- **Подвох**: реферал требует обязательной подписки — без неё `is_joined()`
  всегда true и каждый ожидающий подтверждается автоматически.

## Подарочные коды / redeem

- Админы создают коды из панели флагами в любом порядке: `30d es 1u` → 30 дней,
  ранг Esfandyar, 1 использование (`<n>d` — дни, `<n>u` — использования,
  сокращения рангов `da/se/es/so/ro`).
- Коды — 8 символов из однозначного алфавита (без `0/O/1/I`), чтобы чисто
  проходить в deep-link `?start=`.
- **Скользящий срок 7 дней**: код рождается с `now + 7d`; каждое использование
  сбрасывает окно; после истечения он вычищается (`spawn_redeem_sweeper`).
- `max_uses` ограничивает число использований; `redeem_redemptions` (PK
  `code,user_id`) обеспечивает одно использование на пользователя.

## Обязательная подписка

Гейт обязательного членства в канале, срабатывающий после выбора языка и до любой
фичи:

- Членство **кешируется в Redis**, чтобы гейт не молотил API Telegram на каждом
  действии.
- Кеш держится тёплым за счёт **прослушивания обновлений `chat_member`**
  (`on_chat_member_update`) — в момент подписки или выхода Redis обновляется без
  дополнительных вызовов API.
- Зелёная кнопка «Я подписался» форсирует **живую** перепроверку в обход кеша.

Обязательная подписка также служит якорем доверия для подтверждения рефералов
(см. выше).

## Админ-панель и мониторинг

Колбэки только для админа (`admin:panel`), закрытые `ADMIN_USER_ID`:

- **Статистика** — счётчики событий по фичам (`stats_events`) и число
  пользователей (`stats_users`).
- **Трафик** — байты загрузки/выгрузки по пользователям и успешность выгрузки
  (`stats_downloads`); время первой выгрузки штампуется в `stats_users`.
- **Ошибки (за 24 ч)** — каждая ошибка фичи записывается (`stats_errors`, лимит
  500 символов) и рендерится по запросу, так что триаж возможен прямо из Telegram.
- **Операции** — управление замком обязательной подписки и генерация подарочных
  кодов без выхода из чата.
- **Рассылка** — всем известным пользователям через `copy_message` или
  `forward_message`, опционально с пином, с троттлингом 15 сообщений/с (задержка
  67 мс); заблокировавшие бота автоматически помечаются `is_blocked = true`.

## Trace-логирование

Каждое действие пользователя несёт один **trace id**, протянутый через все
хелперы, так что `rg trace=N` воспроизводит действие целиком по порядку. Два вида
строк:

```
[<domain> trace=N actor] user=@<u> id=<id> rank=<R> clicked=<cb>    # один раз, на входе
[<domain> trace=N event=<step>] k=v => ok|fail err=..|pass|blocked  # на шаг, ДО его выполнения
```

Отсутствие строки event означает, что шаг не был достигнут — само отсутствие и
есть сигнал. Секреты никогда не появляются: токен бота редактируется до того, как
любая строка ошибки попадёт в journald, `stats_errors` или админ-панель ошибок
(ошибки `frankenstein` встраивают полный URL запроса, содержащий токен). ID
усекаются до первых 6 символов.

Пример (падает на захвате CPU — `cores=[]` и есть улика):

```
[upscale trace=43 actor] user=@parsa id=671234… rank=Dalavar clicked=upscale:model:realesrgan-x4plus
[upscale trace=43 event=quota_check] used=2 limit=3 => pass
[upscale trace=43 event=cpu_acquire] => cores=[]
```

Смотреть: `journalctl -u rostam -n 300 | rg trace=` (dev: `-u rostam_dev`).
Макросы в `src/log.rs` (`log_actor!`, `log_actor_id!`, `log_ev!`) — никогда сырой
`eprintln!`.

Хендлеры запускаются через **`spawn_user_task`**, а не голый `tokio::spawn`:
`tokio::task_local!` не пересекает границу spawn, поэтому голый spawn терял язык
пользователя (молча отдавая персидский) и ронял защиту drain при остановке. Голыми
остаются только долгоживущие демоны в `src/app/startup.rs` — их конверсия не дала
бы drain дойти до нуля.

## Конфигурация (`.env`)

Установщик создаёт `.env` из `.env.example`. Ключевые значения:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | **обязательна** — от @BotFather |
| `ADMIN_USER_ID` | Telegram-id с доступом к админ-панели и кешу эмодзи |
| `DATABASE_URL` | `postgres://postgres:postgres@localhost:5432/ros_telegram_bot` (prod: `..._production`) |
| `REDIS_URL` | по умолчанию `redis://127.0.0.1:6379` |
| `BOT_API_BASE_URL` | `http://127.0.0.1:8081` (prod `:8082`; пусто → официальный API, лимит 20 МБ) |
| `HEALTH_PORT` | порт health + метрик, по умолчанию `14380`; **в dev обязательно `14381`** |
| `TESTAPI_ENABLED` / `TESTAPI_PORT` | включение локального test API (`1`) и его порт (по умолчанию `14379`) — требует `--features testapi` |
| `COOKIE_REFRESH_ENABLED` | `false` в dev, `true` в prod |
| `SEP_BIND_HOST` | адрес bind для separation-service; по умолчанию `127.0.0.1`, менять только внутри контейнера |
| `DENO_PATH` | путь к бинарю deno (по умолчанию `/opt/deno/bin/deno`) |
| `IPINFO_TOKEN`, `ABUSEIPDB_KEY` | необязательное обогащение IP-lookup |

Цены рангов и (пока неактивный) `buy_url` лежат в `config/config.yml`;
пользовательские строки — в `config/i18n.json` для всех четырёх языков, с
перезагрузкой в рантайме через `i18n::reload()`.

Все пути фич (`files/models/*`, `models/piper/*`, `config/i18n.json`) разрешаются
**относительно рабочего каталога бота**, поэтому systemd-юнит обязан задать
`WorkingDirectory`.

```bash
curl http://127.0.0.1:6589/health        # separation + CPU-брокер

```

## Известные ограничения

- **Покупка ранга полностью ручная.** `buy_url` в `config/config.yml` неактивен, и
  платёжного кода нет; страница магазина ведёт к админу. Это намеренно.
- **У `separation-service` нет аутентификации эндпоинтов.** Он слушает loopback
  (`127.0.0.1:6589`), что закрывает доступ извне, но не аутентификацию — придётся
  менять 9 Rust-билдеров запросов и 5 дублирующихся констант `SEP_BASE`.
- **`rostam.service` (production) всё ещё работает под root**, вместе с
  принадлежащими root файлами в `production/`. Dev-юнит усилен, production
  намеренно оставлен как есть. Рецепт в [plans/README.md](plans/README.md).
- **Демон `surge` (:1700)** аутентифицирует бота через файл токена, принадлежащий
  root (`/root/.local/state/surge/token`); если бот работает не под root и без
  доступа к нему, `tools:surge` вернёт 401.
- **30-секундный graceful-drain** (`src/app/mod.rs`) короче реальных задач —
  десятиминутный STT всё равно обрывается.
- **Карты флагов отмены перезаписывают вместо отказа** (`ACTIVE_STT_JOBS`,
  `ACTIVE_DENOISE_JOBS`, `register_upscale`), поэтому вторая параллельная задача
  пользователя сиротит флаг отмены первой, и «отмена» отменяет только последнюю.
- **AI-эндпоинты testapi — заглушки** (`/test/stt/recognize`,
  `/test/separation/submit`, `/test/gwm/detect`, `/test/denoise/process`,
  `/test/tts/generate`, `/test/deoldify/colorized`, `/test/nobg/process`) — они
  собирают готовый ответ вместо вызова хендлера, которому нужны медиа-фикстуры и
  ONNX.
- **Firefox cookie-пулу нужен X-дисплей**; на headless-сервере обновление
  YouTube-cookie не запустится (YouTube работает и без cookies). Включается через
  `COOKIE_REFRESH_DISPLAY` или запуск под Xvfb.
- **Бинарь `deep-filter`** качается из релизов DeepFilterNet; если ассет
  недоступен, шумоподавление и денойз в STT деградируют (базовый STT работает).
- **Локальный Bot API** требует `api_id`/`api_hash` Telegram с
  <https://my.telegram.org>; без них используйте `--skip-bot-api` (официальный
  API, лимит загрузки 20 МБ).
